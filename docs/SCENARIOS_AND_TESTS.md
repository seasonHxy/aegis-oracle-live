# 使用场景与测试清单

本清单描述继承场景及 0.2 真实行情升级后的能力，增量验收见 [真实行情验收](LIVE_VALIDATION.md)。公共测试网支持不等于已经完成公共测试网验证。单签名者验签不等于去中心化共识。

## 使用场景

| 场景 | 谁使用 / 如何使用 | 当前交付 | 对应验证与边界 |
|---|---|---|---|
| DeFi 抵押估值原型 | 协议开发者通过 `CollateralLens.quote` 读取 ETH 的美元估值及示例借款额度 | 已实现只读估值，固定 70% LTV | 本地链验证 2 ETH = 6000 USD，额度 4200 USD；不实现存款、借款、还款或清算 |
| EVM 应用读取外部价格 | 合约开发者接入 `AegisOracle.latestPrice` | 已实现授权签名、序号与时效检查 | 正常读取及过期/暂停/禁用拒绝；仅本地链端到端验证 |
| 多行情源质量检查 | 数据工程师以 dry-run 采集交易所报价，检查异常来源及独立性 | 已接入 Coinbase、Kraken、Bitstamp 的 USD 最新成交，保留通用 REST 适配器 | 有确定性解析/HTTP 测试及独立真实采样证据；模拟配置仍明确标识 |
| 报价服务运维演练 | 运营者观察状态页，监控 `/api/status`、`/healthz` | 已实现来源错误、发布状态、价格年龄与交易显示 | HTTP 200 → 来源故障 503 → 恢复 200；未内置外部告警推送 |
| 交易中断恢复演练 | 服务重启后读取交易日志，恢复未确认交易 | 已实现先持久化后广播与相同字节重播逻辑 | 已验证停止出块、pending、重启后恢复；未验证所有 RPC 丢交易或交易替换情形 |
| Rust + Solidity 开发与教学 | 开发者用一键脚本演示采集、聚合、签名、上链、估值全流程 | 已实现本地 Anvil 演示和中文页面 | 可展示正常价格、异常剔除、防重放、故障恢复；无须真实资金 |
| 公共测试网接入试点 | 开发者配置可信 RPC、真实行情与独立报价钱包 | 程序允许 Sepolia / Base Sepolia | 尚未实际部署验证，需提供行情接口、测试币、密钥与配置；模拟报价禁止在公共测试网发布 |
| HIP-3 喂价开发 | HIP-3 开发者独立运行 `legacy/hip3` 中的 Python 实现 | 保留原有批次、格式化和 SDK 适配能力 | 25 项原测试通过；没有实际发送 HIP-3 更新，不是 Rust/EVM 双通道同步发布 |

## 场景测试矩阵

| 测试输入 / 操作 | 预期结果 | 已有覆盖 |
|---|---|---|
| 3000、3001、2999、9000 四个来源报价 | 剔除 9000，聚合价格 3000，保留 3 个独立组 | Rust、迁移对照、端到端 |
| 多接口来自同一底层源 | 不把接口数量当独立来源数，检查最低组数量 | Rust、Python、迁移对照 |
| 重复来源、零价格、负价格、过多小数 | 拒绝无效输入，不形成可发布报告 | Rust；合约另测零价格 |
| 过期 / 未来时间戳 | 无效报价不计入 quorum；不足时阻止发布 | Rust、Solidity、端到端 |
| REST 缺少时间戳或 JSON 损坏 | 来源校验失败；有效来源不足时阻止发布 | 端到端 |
| 买卖价差或 IQR 离散度过大 | 聚合拒绝 | Rust |
| 相比上次已确认价格大幅跳变 | 熔断，不推进链上报告序号 | Rust、端到端 |
| 两个 HTTP 来源返回 503 | 有效来源不足，状态 blocked，健康接口 503 | 端到端 |
| 来源故障后恢复 | 无须重启，重新进入正常状态，健康接口 200 | 端到端 |
| 合法报告签名与价格 | 合约保存，checked 接口返回相同价格 | Solidity、端到端 |
| 错误签名者、篡改价格、坏签名长度、高 s 签名 | 合约拒绝 | Solidity |
| 重复序号、零序号、时间倒退 | 合约拒绝 | Solidity |
| 同签名用于不同链或不同合约 | EIP-712 域不匹配，拒绝 | Solidity；Rust 另测 domain 分离 |
| 有效期过长、未知 feed、离散度超限 | 合约拒绝报告 | Solidity |
| 暂停、禁用、尚无报价、价格过期 | checked 价格接口拒绝读取 | Solidity；过期另有端到端 |
| 管理员权限与两步所有权交接 | 非管理员拒绝，接受交接前 owner 不变 | Solidity |
| 收紧 feed 最大年龄 | 已存价格按新配置重新检查 | Solidity |
| 同状态文件重复启动或跨模式复用 | 文件锁 / 身份校验拒绝 | Rust |
| 状态文件损坏 | 拒绝加载，不静默重置基准 | Rust、Python |
| 停止本地链出块并重启服务 | 保留 pending 日志，出块后恢复，无遗留 pending | 端到端 |
| 两次正常发布后执行失败周期 | 已确认序号保持 2，不因失败周期增加 | 端到端 |
| 2 ETH 输入估值合约 | 6000 USD 估值、4200 USD 示例额度 | Solidity、端到端、浏览器 |
| 浏览器输入负数 | 显示暂不可用 | 上轮浏览器交互验收 |

## 复现命令

在项目根目录执行：

```bash
# 全套检查（包含构建与端到端，本机需要允许监听 loopback）
make check

# 只查看可交互的本地演示
python3 scripts/demo.py

# 已构建后只运行端到端测试
python3 scripts/demo.py --check --no-build
```

首次运行需 Rust、Foundry 和 Python，以及下载编译依赖。本机 Cargo 缓存权限处理见 [验收记录](VALIDATION.md)。

## 尚未实现或尚未验证

- **完整借贷协议与清算**：目前只有只读估值合约，70% 仅为演示参数。
- **生产行情与长期稳定运行**：已接入三个交易所的公开接口；未获得生产供应商 SLA，未完成延迟基准、负载/压力测试和长时间运行测试。
- **公共网络发布**：公共测试网尚未部署验证；Rust 发布器明确禁止主网。
- **多节点安全**：没有多签名者共识、主备选举、HSM/KMS 或分布式 nonce 协调。
- **复杂交易故障**：自动加价替换、外部交易占用 nonce、节点遗忘后重播、深度链重组未做完整故障验收。
- **多资产与其他资产类别**：Rust 一进程一 feed；没有多 feed 原子发布、股票休市语义、汇率转换或资产净值模型。
- **独立安全审计**：单元、模糊与本地端到端测试不等于审计，也不证明授权签名者报价真实。

后续若接入真实资产，需按实际协议补充数据操纵、价格精度、清算行为、管理员操作及部署环境测试；不能直接把演示结果作为生产验收。
